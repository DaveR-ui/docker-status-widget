# ADR-0018: Retrofit the corpus to documentation-onrails v1.4

## Problem

The corpus predates documentation-onrails v1.4. It was bootstrapped against an earlier revision of
the methodology, under the methodology's former name, and every corpus-level artifact sat under
`docs/`: the entry point, the two generated artifacts and the vendored validator copy. The
repository root already carried a human `README.md`, so the tree had **two** things that read as a
"start here", and the schema layer still used the pre-v1.4 procedure container. The methodology
has since moved to v1.4, renamed itself, and settled the consumer layout: one root entry point,
generated artifacts at the root, the validator at the root, and a protocols folder instead of the
older procedure container.

Two retrofit paths were available. The brownfield ratchet — apply the contract to new and touched
files only — would leave the corpus half-migrated, with the old entry point and the old folder
spelling living on beside the new conventions. The human chose the **deliberate big-bang**: the
whole corpus moves to the v1.4 layout in one batch, and the record of what changed lives here
rather than in edits to the append-only history.

## Solution

One batch, itemized. Nothing outside the documentation corpus changes; the shipped widget, its
tests, its packaging and its release site are untouched.

1. **Adopt documentation-onrails v1.4**, referenced by URL
   (`https://github.com/DaveR-ui/documentation-onrails`). The upstream guidelines are **not**
   vendored: this corpus keeps the shapes its templates encode and cites the normative text by
   `.../blob/main/guidelines/NN-....md` URL.
2. **The root `README.md` is THE single entry point.** It keeps every line of human-facing content
   it had and gains the context-doc frontmatter (`last_updated`, `status`, `description`, `tags`,
   `version`, `doc_language: en`, `related`) plus the corpus-navigation section folded in from the
   old router: the navigation table, the folders table, the generated-navigation notes, the corpus
   rules, the schema-layer table and the decision-records table. It points at
   [`docs/project.md`](../project.md) as the canonical agent-facing file — there is exactly one
   "start here" in the repo.
3. **The old corpus router under `docs/` is retired.** Its `readme.md` is superseded by the root
   `README.md`, which carries every fact it held (navigation, folders, generated aids, rules,
   schema layer, decision records). ADR-0001's clause naming that file as the entry point is
   superseded **by this record**; ADR-0001 itself is append-only and is not edited.
4. **The procedure container moved: `checklists/` under `docs/` is now `docs/protocols/`.**
   `bootstrap-checklist.md` → `bootstrap-protocol.md` (id `bootstrap-protocol`) and
   `new-note-checklist.md` → `new-note-protocol.md` (id `new-note-protocol`), each carrying
   `moved_from` provenance, `category: protocols` and the `protocol` tag. Their bodies — the
   checkbox procedure shape — are preserved verbatim in substance, re-worded from "checklist" to
   "protocol". The `checklist` class retires from the corpus's doc-class registry in favour of
   `protocol`; this supersedes the checklist half of the registry ADR-0005 fixed (a class change
   needs a record, and this is that record; the four body-shape classes themselves are untouched).
5. **The validator moved to the repository root**, so `ROOT` is the repo root and
   `node validate.js` / `node validate.js --write` run from there. Its behaviour — every check,
   both severities, the output format, the exit codes, the write-if-diff renderer — is unchanged;
   only collection and classification adapt, in exactly four places: dot-directories and
   build/vendor directories (plus `dist/`) are skipped; the entry points are the root `README.md`
   and `docs/project.md`; the schema folders map at their `docs/` depth (`docs/adrs/` → adr,
   `docs/templates/` → template, `docs/protocols/` → protocol) with the five slice folders
   staying notes behind their hubs; and the category warning compares against the folder's final
   path segment. The adaptation header inside the file enumerates the same list.
6. **The generated artifacts moved to the root** as `index.md` and `tag-index.md`, marker regions
   and all, regenerated by the same command.
7. **The methodology name changed.** Every mention of the old slug and its spaced-out form in live
   prose is now `documentation-onrails`, and every citation of a specific upstream file uses the
   `.../blob/main/guidelines/NN-....md` URL form. The old spelling survives only inside the
   append-only records listed under Common mistakes.
8. **The corpus keeps its topic folders under `docs/`.** The consumer layout also allows a
   `docs/context/` tier for strategic docs; this corpus's strategic docs are already at home in
   its five slice folders behind their hubs. Moving them would re-write every link in the corpus
   for no contract change — the topics keep their hub, the validator keeps classifying them as
   notes, and `docs/context/` stays unmapped for the day a strategic doc actually needs it. This
   is the ratchet, applied to the one move that was available and rejected.

## When to use

When reading back why the corpus's layout differs from ADR-0001's text, or when a reviewer asks
where the entry point, the generated artifacts and the validator live and why. Also when deciding
where a new document belongs: schema folders stay hub-less and register through the root
navigation table.

## When not to use

Not as permission to edit ADR-0001, ADR-0002, ADR-0005 or any other append-only record — their
historical text stays, and this record carries the deltas. Not as a mandate to move the corpus
root to `docs/context/` later: that move needs its own successor record with a real contract
change behind it.

## Examples

What the batch touched, in one view:

- Root: `README.md` (frontmatter + corpus-navigation section + layout block),
  `index.md`, `tag-index.md`, `validate.js`.
- `docs/`: `project.md` (Commands, Repository Structure, Context Index, working-directory
  quirks), the retired router and the retired validator copy removed, `protocols/` created from
  the old procedure container, `adrs/adr-0018-onrails-v1-4-retrofit.md` added and registered in
  `adrs/adr-index.md`.
- Templates: the upstream citations and the wikilinks to the two migrated protocols repointed;
  every touched file bumps `version`.
- `tools/README.md` gains the note contract so the root-level scan classifies it.
- Workflows: the two docs-gate commands run `node validate.js` from the repo root.

## Common mistakes

- **Append-only history, left unedited on purpose.** ADR-0001's body still names the old router
  as the entry point and the old generated paths, and its References still link to the retired
  router (`docs/adrs/adr-0001-corpus-location-and-entry-point.md:74`); ADR-0002's body still lists
  the old procedure folder, describes a validator vendored under `docs/`, and links to that retired
  copy (`docs/adrs/adr-0002-lowercase-naming-convention.md:79`); ADR-0005's and ADR-0013's bodies
  still cite the methodology's old slug and the old validator path. Rewriting them would falsify the
  archaeology, so the two now-dead reference links stay and are recorded here instead — the corpus
  gate reports both as `dangling-link` findings until a human authorises repointing the two link
  targets (the decision prose in both records is untouched and needs no repair).
- **A stale comment in an off-limits file.** `.github/scripts/sync-manifest.mjs` still names the
  validator's old path in a comment. The widget's stability constraint puts that directory off
  limits for a docs-only change, so it is recorded here rather than edited.
- **Two entry points again.** The root `README.md` is the human entry point and
  `docs/project.md` is the canonical agent-facing file; a second "start here" reintroduces the
  maze this retrofit removed.
- **Migrating the folder but not the class.** Renaming the procedure container without moving
  `category:` and the validator's `NOTE_CLASSES` leaves the files classified as plain notes — the
  exact half-done-rename failure the class registry exists to prevent.
