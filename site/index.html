Docker Status

The two things every developer actually needs, one click away in the panel: a Docker daemon that is running, and the meme video saved before it disappears.

Latest release 1.0.0 2026-10-18 release notes

Docker Status 1.0.0 — released 2026-10-18. Version 1 — stable, the first finished release of the widget. A KDE Plasma 6 widget for the Docker daemon: it tells you the state at a glance, starts it without a password prompt, stops it behind a deliberate confirmation, and downloads the YouTube or X link you just pasted — no terminal, no browser tab, no sudo dance.

What it does

Panel, at a glance

A theme icon, dimmed while the daemon is down, plus a severity dot. Nothing else. The count and the state text live in the popup, so the panel stays quiet.

Four states, not two

State is reported honestly, and a probe that fails is never drawn as a daemon that is stopped:

Daemon state, severity and colour
StateSeverityColour
activepositivegreen
inactiveneutralorange
failednegativered
unknownmutedgrey

Start without a password

One click, no prompt. A single polkit rule grants exactly one action id, one unit (docker.service) and one verb (start), from a local active session in the wheel group. It is not widened for anything else, and installing it is a separate, explicit command.

Stop behind a confirmation

Stopping the daemon stops every running container, so the Stop button arms on the first click and runs on the second, and the confirmation expires. Stop is deliberately outside the grant, so polkit asks for your password as well. Two safeguards, on purpose.

The popup

Daemon state, a running/total count with a bar, the start/stop row and the refresh, Podman Desktop and update controls — all in one pinned status card. Below it the containers are listed flat, grouped by Docker Compose project, each group carrying its own counter and its own collapse, and — for compose-backed groups — its own play/stop controls; the list scrolls, so the widget never changes size as containers come and go. Miscelánea is the pinned card at the bottom, holding both the video-download row and the shutdown countdown. No footer.

Countdown to Extinction

A shutdown countdown with a wall-clock deadline you set in minutes and a one-second ticker, so it survives a suspend. Neither arming nor cancelling needs root, and the power-off runs the fixed command — the configured minutes only size the deadline. It lives inside Miscelánea, and an armed countdown is never collapsed away.

Save the meme before it disappears

Paste a YouTube or X link into the popup and yt-dlp fetches it into the configured folder, with cookies from the configured browser. This is the one place user input reaches a command, and it is bounded: https only, an exact host allow-list, a length cap, no quotes or backslashes, and every interpolated value shell-quoted. It shares the Miscelánea card with the countdown.

An honest update check

The widget asks one fixed manifest whether a newer release exists, and says so with a muted line and one indicator. Nothing is said while it is current, and a failed check draws nothing at all — the version is authored once, in metadata.json.

Configured, not compiled

Poll interval, panel icon, container list, Podman Desktop path, download row, folder, yt-dlp binary, JS runtime, cookies browser, shutdown countdown minutes and update-check interval — all on the config page. Every value that reaches a command is validated before it is assembled, and a refused value falls back to its safe default.

What it looks like

Install

git clone https://github.com/DaveR-ui/docker-status-widget.git
cd docker-status-widget
./install.sh install          # the widget itself — unprivileged, reversible
./install.sh install-polkit   # optional, sudo: makes "Start daemon" passwordless
./install.sh status           # what is installed, and whether Docker is up

Then right-click the panel or the desktop → Add Widgets… → search “Docker Status”. On the desktop the full widget is shown directly; in the panel it collapses to the icon and the severity dot and expands into a popup. If it does not appear, restart plasmashell: 

kquitapp6 plasmashell && kstart plasmashell

Installing the widget needs no root, and removing it is one command. The polkit rule is the only privileged step, it is a separate command on purpose, and it never happens implicitly.

Requirements

  • KDE Plasma 6 (X-Plasma-API-Minimum-Version: 6.0) on Wayland. Verified on Plasma 6.7.4, plasma5support 6.7.4 and polkit 127.
  • Docker with docker.service. Only that unit is supported: no rootless Docker, no user-scoped daemon.
  • For downloads only: yt-dlp on plasmashell’s PATH, a JavaScript runtime (node or deno) for YouTube, and a signed-in browser profile for cookies.

How the update check works

The site also serves a machine-readable release manifest at a fixed address: 

https://dave-r-ui.github.io/docker-status-widget/latest.json

Every installed widget fetches that file every few hours and compares the manifest’s version with its own; when the online one is newer, the widget says so instead of letting you run an old build. The manifest is generated from the same metadata.json the widget is packaged with, so the two cannot drift: 

{
  "app": "io.github.daver-ui.dockerstatus",
  "name": "Docker Status",
  "version": "1.0.0",
  "released": "2026-10-18",
  "url": "https://github.com/DaveR-ui/docker-status-widget/releases/latest"
}

A JSON endpoint keeps that check robust: no scraping a page, no matching a heading, no guessing when the layout changes. The version badge at the top of this page is written by the same file, and it falls back to the value in the HTML when the fetch fails.
